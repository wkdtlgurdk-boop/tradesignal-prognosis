# 실적발표 스크리닝

분기마다 "이번 주 실적 발표 기업 중 시총 2,000억↑, 매출·영업이익 20%↑(YoY / QoQ)"를 정리하는 폴더.

- 결과 md: `YYYY-NQ_실적발표.md` (분기당 1개)
- `tools/`: 2026년 3분기에 실제로 돌린 스크립트 (환경변수 `DART_API_KEY` 필요)

## 분기별로 다시 돌릴 때

1. `DART_API_KEY` 설정. 시총은 `m.stock.naver.com`(네이버 모바일) API 사용
2. 접수 기간·분기 코드 수정
   - 공시 목록: `list.json`의 `bgn_de`/`end_de`, 분기보고서는 `pblntf_detail_ty=A003`
   - `fin.py`: `bsns_year`, 당분기 `reprt_code`(1Q 11013, 반기 11012, 3Q 11014, 사업 11011), 직전 분기 코드
3. 실행 순서: (목록 수집 → `filings.json`) → `mcap.py` → `fin.py` → `retry.py`(요청제한 재시도) → `fill.py`(API에 아직 없는 최근 접수분은 원문 파싱) → `analyze.py` → `gen_md.py`
4. 직전 분기 값: 1Q 보고서는 직전 분기가 전년 4Q라 사업보고서 − 3Q 누적으로 계산해야 함(현재 스크립트는 3Q 기준)

## 알려진 한계

- 마감일이 주말이면 다음 월요일 제출분이 따로 생김 → 다음 주에 추가 갱신
- 금융업(은행·증권·보험)은 매출/영업이익 계정이 달라 제외
- 접수 당일~다음날은 DART 재무 API에 데이터가 없을 수 있어 원문 파싱으로 보완
